# 论文速读：PLAYWORLD-BENCHMARKING-WORLD-MODELS-WITH-AGENT-PLAYERS-OVER

## 一句话总结
本文提出 PlayWorld，一个面向视频世界模型的多智能体交互式评估基准。通过引入多模态 Agent Player 以人类玩家视角追踪长程目标，PlayWorld 在 171 个人工标注场景上对 9 个代表性世界模型进行了四维度评估，揭示了当前模型在空间一致性和持久状态演化方面的核心瓶颈。

## 研究问题与动机
- **现有基准依赖预定义动作轨迹，无法公平比较不同模型**：现有世界模型基准（如 WorldScore、WorldMark 等）使用针对特定案例预定义的相机/动作轨迹（如三个 → 指令旋转 360°），但不同模型的"动作粒度"和响应速度差异显著——同一组指令在某些模型中可完成完整旋转，在另一些模型中只能部分完成，导致生成的几何一致性分数不可比。
- **封闭式 Web 模型需要人工交互，成本高且存在主观偏差**：Genie 3、HappyOyster 等闭源模型只能通过 Web 界面使用，人工评估既耗时又容易引入偏见，缺乏自动化评估协议。
- **长程目标下的人类评测范式未被现有基准覆盖**：真实用户评估世界模型时，通常追求高层长程目标（如"绕物体转 360 度"或"走进水里看涟漪"），而非核对预定义轨迹；现有基准的固定轨迹设计无法捕捉这一评测范式。
- **视频质量指标与交互能力之间存在割裂**：已有评测多侧重像素级保真度和低层级感知质量，难以衡量大视角变化下的一致性、交互合理性以及长程目标是否达成。

## 核心贡献（创新点）
1. **提出 PlayWorld 基准**：构建 171 个人工标注场景、50 种动作模式，覆盖 10–60 秒的长程交互 rollout，首次以"长程目标 + 自适应动作"范式替代传统固定轨迹评估。与已有工作相比，其核心区别在于以目标导向的闭环交互替代预定义开环执行。
2. **设计多模态 Agent Player**：引入可替换的多模态智能体（如 Claude/Gemini），在每个交互步根据生成帧和执行历史自适应决策（Keep/Stop/Extend/Correct/End），使同一长程目标在不同模型上的达成过程可比。与已有工作相比，这是首个支持在线适配动作粒度的自动评测框架。
3. **提出四维度 VQA Rubric Verifier**：围绕几何一致性、交互保真度、视线外演化和洞察演化四个核心能力维度设计样本级 VQA 评分体系，每维度设有前置验证门（如轨迹有效性检查）。与已有工作相比，该方法首次将复杂交互语义拆解为可自动判定的证据族问答，而非依赖像素级相似度。
4. **系统性评估 9 个 SOTA 世界模型并揭示能力边界**：覆盖 5 个闭源和 4 个开源模型，发现当前模型在持久状态演化（尤其是视线外演化和洞察演化）方面仍是主要瓶颈，同时揭示"强轨迹控制 ≠ 强世界模型能力"的背离现象。

## 方法详解

### 3.1 Agent Player 设计
Agent Player 由**可替换的多模态 Agent 模型**和**Agent 接口**两部分组成，形成闭环交互环路：

- **Agent 模型决策**：系统保留人类标注的基本动作序列作为共享初始参考（而非完全从零规划），在每个交互步观察生成帧、已执行动作、场景描述和目标后，做出五种决策之一：
  - **Keep**：保留计划动作，继续当前按住或进入下一步
  - **Stop**：提前终止当前动作（当预期视觉状态已达成）
  - **Extend**：延长动作按住时间（当需要更多移动）
  - **Correct**：修正或跳过下一个计划动作（当观测状态与参考序列不符）
  - **End**：仅当 Agent 判定长程目标及其所需观测均已完成后终止
- **Agent 接口执行**：接收初始帧和基本动作序列（W/A/S/D、↑/↓/←/→、WAIT），将其转换为各模型的原生控制输入；每步捕获生成帧返回给 Agent 模型，循环执行直至收到 End 指令或 40 步交互预算耗尽。对于 Web 模型，通过浏览器自动化实现控制派发和帧捕获。

### 3.2 PlayWorld 基准构建
- **数据来源**：从 Pexels 和 Google Images 收集候选图像，涵盖自然、城市和幻想环境，包含人物、动物、车辆等主体
- **标注流程**：用 Gemini 3.1 Pro 生成环境描述（人工校验修正）→ 定义长程目标及视觉可验证完成条件 → 编写基本动作序列 → 构造样本特定的 VQA 评分细则
- **覆盖范围**：171 个人工标注案例、50 种动作模式、>820 道 VQA 问题、>1,400 个交互视频

### 3.3 VQA Rubric Verifier
采用 Gemini 3.1 Pro 回答样本级 Yes/No 问题，按维度赋权后聚合为 1–5 分。四个核心维度如下：

**几何一致性（Geometry Consistency）**：
- 前置验证：轨迹有效性（Trajectory Validity）
- Scene Identity：物体身份、数量、纹理、材质、颜色是否保持（如 360° 旋转后壁画颜色和形状是否一致）
- Spatial Consistency：物体相对位置和场景布局是否合理（如红车最初在绿车右侧，穿越街道后回头看是否仍在左侧）

**交互保真度（Interaction Fidelity）**：
- 前置验证：主体和可达性（Subject and Reachability）
- Contact and Collision：是否与障碍物碰撞而非穿过
- Motion and Causality：运动是否符合合理运动学（如保持接地脚步、无漂浮）
- Visual Response：进入水中是否产生波纹、水花等物理反馈

**视线外演化（Out-of-sight Evolution）**：
- 前置验证：轨迹有效性
- Reappearance Consistency：重新出现时是否为同一实体
- Hidden-State Evolution：未观察期间状态是否合理推进（如未完成的画作是否有新增内容）
- Physical Causality：重现状态是否可以合理地从隐藏演化中推导

**洞察演化（Insight Evolution）**：
- 无需轨迹验证（固定机位观察）
- Identity and State Progression：对象是否持续存在并随时间推进状态
- Motion and Physical Plausibility：是否出现静止、非渐进重复动作、突兀转换
- Temporal Scene Consistency：检测周围环境的意外变化

**评分公式**：
$$R_d = \frac{\sum_{j \in A_d} w_j a_j}{\sum_{j \in A_d} w_j}, \qquad S_d = 1 + 4R_d$$
其中 $a_j \in \{0, 1\}$ 为二元答案，$w_j$ 为权重（一般问题为 1，核心要求问题为 2，不适用问题为 0），$A_d$ 为适用问题集合。Overall 为四个维度分数的未加权均值。

### 3.4 基础能力评估
使用 VBench、Omni-WorldBench、MemoBench、HyDRA 的自动指标评估视频质量和动作可控性：
- **视频质量（7 项）**：美学质量、成像质量、运动平滑度、时序闪烁、时序一致性、深度稳定性、主体一致性
- **动作可控性（2 项）**：平移通过率（Translation Error < 0.3）、旋转通过率（Mean Geodesic Rotation Error < 45°），使用 VGGT 估计相机位姿
- **基础能力得分**：将 9 项指标的平均排名转换为百分比

## 实验与结果

### 评测模型
- **闭源（Web 接口）**：Genie 3、HappyOyster、LingBot-World、LingBot-World2、HY-World2
- **开源（本地推理）**：SANA-WM、Hunyuan-GameCraft-2、HY-WorldPlay、Matrix-Game-3.0

### 主要结果（VQA 四维评分，1–5 分，越高越好）

| 模型 | 几何一致性 | 交互保真度 | 洞察演化 | 视线外演化 | 综合 |
|------|-----------|-----------|---------|-----------|------|
| **Genie 3** | **2.74** | **2.40** | 1.51 | **1.81** | **2.12** |
| HappyOyster | 2.54 | 2.15 | 1.47 | 1.54 | 1.92 |
| LingBot-World2 | 2.04 | 2.13 | **1.95** | 1.16 | 1.82 |
| LingBot-World | 2.11 | 2.23 | 1.33 | 1.43 | 1.78 |
| HY-World2 | 2.14 | 2.06 | 1.13 | 1.09 | 1.61 |
| SANA-WM | 1.72 | 1.89 | 1.13 | 1.16 | 1.48 |
| Hunyuan-GameCraft-2 | 1.62 | 1.52 | 1.21 | 1.31 | 1.42 |
| HY-WorldPlay | 1.12 | 1.63 | 1.01 | 1.08 | 1.21 |
| Matrix-Game-3.0 | 1.30 | 1.25 | 1.00 | 1.00 | 1.14 |

- **Genie 3 在三个维度上取得最高分**，综合得分 2.12；LingBot-World2 在洞察演化上最高（1.95）
- **视线外演化和洞察演化始终得分最低**，是当前模型的主要瓶颈
- **轨迹通过率与 VQA 分数存在背离**：SANA-WM 的轨迹验证通过率较高（整体 80.4%），但 VQA 分数仅 1.48，说明能跟上轨迹不代表具备强世界模型能力

### 轨迹验证通过率

| 模型 | 几何一致性 | 交互保真度 | 视线外演化 | 综合 |
|------|-----------|-----------|-----------|------|
| Genie 3 | 77.1% | 93.5% | 90.7% | 87.1% |
| HappyOyster | 63.8% | 93.5% | 81.4% | 79.6% |
| LingBot-World2 | 58.3% | 85.1% | 93.0% | 78.8% |
| SANA-WM | 62.5% | 88.0% | 90.7% | 80.4% |

### 基础能力评估
- 多数模型在视频质量上表现较好；HappyOyster 基础能力得分最高（76.4%），但这不意味着其长程世界模型能力最强
- 动作可控性普遍弱于视频质量：平移通过率最高 89.6%（Hunyuan-GameCraft-2），旋转通过率最高 67.9%（LingBot-World2）

### Agent Player 分析
- **Preset + Agent 策略最优**：Trajectory Score 和 Human Preference 均最高（Genie 3 上 1.08 / 65.6%，HappyOyster 上 1.12 / 67.4%），Agent 修改动作比例仅 12–15%
- **Claude Haiku 被选为推荐 Agent 模型**：决策延迟最低（3.83s/call），综合质量-效率权衡最优

### 人审对齐
- VQA 指标与人类偏好的 Spearman 相关系数：Overall ρ=0.933，几何一致性 ρ=0.983，交互保真度 ρ=0.933，视线外演化 ρ=0.812，洞察演化 ρ=0.745，全部统计显著（p<0.05）

## 相关工作脉络
1. **VBench / T2V-CompBench**：评估感知质量、时序稳定性和文本对齐，但不评估对用户动作的响应，PlayWorld 弥补了交互响应能力评估的缺失。
2. **WorldScore（Duan et al., 2025）与 WorldMark（Xu et al., 2026b）**：评估相机控制和多视角几何，但使用预定义轨迹，相同控制在不同模型上可能产生不同运动幅度，导致几何不一致性与轨迹失败混淆；PlayWorld 通过自适应动作执行消除了这一混淆。
3. **MIND（Ye et al., 2026）、MemoBench（Chen et al., 2026b）、STEVO-Bench（Ma et al., 2026）**：通过重返可见性评估记忆和视线外演化，但采用固定调度流程，无法根据模型特有的动作粒度和响应速度进行调整；PlayWorld 的 Agent Player 实现了在线自适应。
4. **Omni-WorldBench（Wu et al., 2026）、WBench（Ying et al., 2026）、WorldRoamBench（Xu et al., 2026a）**：引入了多轮导航模式，但无法灵活组合为多样化长程轨迹，也无法在生成观测偏离预期状态时在线调整；PlayWorld 支持任意长程目标的闭环自适应交互。
5. **Genie 3（Google DeepMind, 2025）与 HappyOyster（Alibaba Cloud Community, 2026）**：闭源 Web 世界模型，PlayWorld 通过浏览器自动化接口对其进行了首次系统化公开对比评测，填补了闭源模型可比评测的空白。
6. **SANA-WM（Zhu et al., 2026a）、HY-World2（Team HY-World et al., 2026）、Matrix-Game-3.0（Wang et al., 2026）**：开源世界模型代表，PlayWorld 在同一协议下对开源与闭源模型进行了统一评测，揭示了开源模型在轨迹控制和世界演化方面的相对短板。

## 局限性与未来方向
- **闭源模型的接入依赖浏览器自动化**：对于无 Web 界面的模型需要本地部署适配器，且某些模型有特定输入要求（如 HY-World2 需要支持全局场景建模的输入图像），导致部分案例被排除，可能引入选择偏差。
- **VQA 评分依赖单一 LLM 判断**：虽然验证了两遍评分的方差很低（mean per-model sample variance = 0.0112），但单次评分仍可能存在系统偏差；推荐使用多次评分取平均以降低不确定性。
- **洞察演化维度的相关性相对较低**（Spearman ρ=0.745）：该维度缺乏明确动作轨迹，自动化评分与人类判断的对齐度弱于其他维度，可能需要更精细的评估设计。
- **Agent Player 的计算开销**：每个交互步都需要 LLM 推理，虽使用 Claude Haiku 降低延迟（3.83s/call），但 40 步预算下的总延迟仍显著高于纯开环评估。
- **评测场景类别有限**：目前覆盖 6 种主体类型，尚未充分探索复杂物理交互（如流体动力学、柔体变形）和多主体协同场景。

## 研究启发与可借鉴点
1. **"参考轨迹 + 在线自适应"的评测范式可迁移**：在需要跨模型公平比较的场景中（如不同机器人策略、不同 LLM 推理链），可借鉴"固定初始参考 + 观测条件自适应"的设计，避免动作粒度差异带来的不公平。
2. **VQA Rubric Verifier 的设计思路可用于其他生成模型的语义评估**：将复杂能力拆解为带前置验证门的样本级 Yes/No 问答，并按相关性赋权聚合，是一种可复用的自动化语义评估框架，可迁移到 3D 生成、多模态对话等方向。
3. **轨迹通过率与能力评分的背离警示了单一指标的局限性**：本研究明确展示了"能走到目标位置 ≠ 能正确维持世界状态"，后续评估应同时报告轨迹控制指标和语义一致指标，避免误判。
4. **闭源模型浏览器自动化评测流程具有工程参考价值**：Agent 接口封装了认证登录、页面导航、渲染状态监测、输出采集等确定性操作，可作为其他 Web-based 生成系统的标准化评测方案参考。
5. **与团队方向的结合机会**：若团队关注世界模型的持久状态管理或长程一致性，可基于 PlayWorld 的 VQA 框架进一步挖掘视线外演化（out-of-sight evolution）和洞察演化（insight evolution）这两个薄弱维度的改进方向，如引入显式 3D 全局表示或时序记忆机制。

## 关键术语表
- **World Model（世界模型）**：能够根据用户动作和当前观测持续生成未来状态的视频生成模型，模拟可交互的开放式环境。
- **Agent Player（代理玩家）**：PlayWorld 中模拟人类玩家的的多模态智能体，通过闭环交互自适应调整动作执行以完成长程目标。
- **VQA Rubric Verifier（VQA 评分细则验证器）**：使用 LLM 回答样本级 Yes/No 问题，按维度赋权聚合为 1–5 分的自动化语义评估模块。
- **Geometry Consistency（几何一致性）**：评估相机运动过程中环境结构、物体身份和空间布局是否保持一致的能力。
- **Interaction Fidelity（交互保真度）**：评估用户动作引发的物理反馈是否合理（如碰撞、运动学、视觉响应）。
- **Out-of-sight Evolution（视线外演化）**：评估目标离开视野后重新出现时是否保持身份一致且状态合理推进。
- **Insight Evolution（洞察演化）**：评估固定机位下持续观察过程中场景和主体的状态是否自然演进而非重置或突变。
- **Trajectory Validity（轨迹有效性）**：VQA 评分的前置验证步骤，判断 rollout 是否遵循了目标所需的轨迹并到达预期观测状态。
- **Preset + Agent 策略**：结合人类标注基本动作序列作为参考与 Agent 在线自适应调整的评价控制策略。

## 可复现要素
- **数据集**：171 个人工标注案例，公开于 https://kxding.github.io/project/PlayWorld/
- **代码**：已开源（GitHub 链接见论文首页）
- **权重**：使用的模型包括闭源 API 模型（Genie 3、HappyOyster 等）和开源模型（SANA-WM、Matrix-Game-3.0 等），各有其各自开源策略
- **关键超参**：交互步上限 40 步；VQA 主流采样 10 FPS、分辨率 384×216、每 25 帧一组 5×5 网格；细节流 0.5 FPS、分辨率 800×450、每 4 帧一组 2×2 网格；平移通过率阈值 Translation Error < 0.3；旋转通过率阈值 Mean Geodesic Rotation Error < 45°
- **Agent 模型**：Claude Haiku 4.5（推荐），也可替换为 Claude Sonnet、Gemini 3.1 Pro
- **VQA 验证器**：Gemini 3.1 Pro
- **相机位姿估计**：VGGT（Wang et al., 2025）
- **主体一致性检测**：YOLO + CLIP
