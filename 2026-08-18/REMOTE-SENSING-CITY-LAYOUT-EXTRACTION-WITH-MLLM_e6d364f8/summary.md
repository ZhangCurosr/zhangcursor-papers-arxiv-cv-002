# 论文速读：REMOTE-SENSING-CITY-LAYOUT-EXTRACTION-WITH-MLLM

## 一句话总结
论文提出 Code-as-City 框架，利用多模态大语言模型（MLLM）将单张俯瞰遥感 RGB 图像转化为**可执行的城市布局程序**；执行该程序可同步生成正交二维语义投影与可渲染三维城市模型，并通过投影实现像素级评估。

## 研究问题与动机
1. 现有遥感输出（检测框、实例/语义掩码、向量边界）仅能提供**图像平面的定位与分类信息**，缺乏持久对象身份、类型化关系、拓扑结构与再生成规则，难以直接作为可维护的城市资产。
2. 程序化/结构化城市表示（如形状文法、CityJSON）在规则或几何已知时很有用，但**起点更早**：需要从单张俯视图恢复实例对象与关系以实例化布局。
3. 现有可执行视觉推理工作（VISPROG、ViperGPT、LayoutGPT、3D-GPT、Holodeck、Code-as-Room）多聚焦通用视觉推理、语言条件生成或室内布局，**缺乏针对户外道路网络与异质土地覆盖的统一程序化城市布局提取**。
4. 需要一种既能保留图像平面像素级度量（IoU 等），又能输出**可检查、可编辑、可同步再生成 2D/3D 视图的结构化代码**的方法。

## 核心贡献（创新点）
1. **提出图像到城市代码的任务定义**：主预测物为可执行布局程序而非终端栅格/矢量；相同命名对象与几何可同时产出正交语义投影与 3D 视图。与检测/分割任务本质区别在于预测空间为可执行代码而非像素标签。
2. **先验引导的分解 MLLM 解析工作流**：先生成五类语义布局先验对齐类别与足迹证据，再由控制器调度三路依赖 MLLM 调用（道路→土地利用与关系→建筑），中间记录被累积而非覆盖。与直接用 MLLM 端到端生成方案的区别在于引入**生成式先验作为平面约束**并保留可追溯生成记录。
3. **确定性归一化 + 受限布局 API + 程序执行与修复机制**：将三阶段记录转换为稳定标识、规范坐标与类型化关系，并用 Python 代码序列化；在超时子进程中执行并做几何/标识/关系检查与预设修复路径。与纯语言生成方案的本质区别在于**结构化校验与可重复执行**保障稳定性。
4. **共享渲染与同步评估协议**：同一布局经 Three.js 渲染器生成斜视 3D，并经正交投影栅格化用于像素级 IoU 评估；任一命名对象或关系编辑可同步重生成两视图。与分离评估（仅 2D 或仅 3D）的本质区别在于**计划与三维一致性来自同一执行产物**。

## 方法详解
- **任务契约**：输入近垂直 RGB 图像 $I$，输出受限程序，执行后得到带类型关系（连通、包含、邻接、服务、对齐）的城市图与渲染器友好的布局；同名称对象与几何同时产出正交语义投影与斜视 3D 视图。目标为**平面图组织**，高度与外观属性为近似。
- **语义布局先验生成**：用图像模型从 $I$ 派生五颜色语义布局先验 $M$，为每轮 MLLM 调用提供对齐的类别与足迹证据；$I$ 提供功能、关系、屋顶外观与近似高度线索。
- **三路有序 MLLM 解析**：
  1. **道路 pass**：恢复中心线、宽度、交叉口与连通性。
  2. **拓扑 pass**（依赖道路记录）：提取开放空间区域与类型化关系。
  3. **建筑 pass**（依赖前序拓扑）：识别独立足迹与重复组。
  坐标归一化至原图像帧，后续 pass 扩展共享对象目录而非替换。
- **提示设计**：以 $M$ 为主平面约束；图构建后用先验连通分量调和建筑、道路面积、运动场与水域几何；高度/外观字段仍来自 $I$，植被与其余几何由图导出。先验起**定位作用**而非作为独立最终分割头或被报告的主要预测。
- **类型化图、受限 API 与有界控制**：确定性归一化产生稳定 ID、规范坐标与类型关系；序列化器将其表达为基于闭合布局 API 的 Python 代码，主要操作为 `add_road`、`add_building`、`add_open_space`、`relate`，模式特定构造器覆盖交叉口与重复建筑组。
- **执行与修复**：在超时子进程中执行生成 JSON，进行畸形几何、重复 ID、无效关系端点检查；失败时走预设修复路径（修复畸形 JSON、拓扑重试、确定性拓扑修复与验证）。控制器负责调度、保留中间产物、执行与故障路由；**不使用视觉自迭代**。
- **共享渲染与评估指标**：道路中心线按估计宽度缓冲，建筑多边形按近似高度拉伸，语义开放空间为低表面；Three.js 生成斜视，正交投影器以固定调色板栅格化相同几何。类 $c$ 的 IoU 为：
  $$\mathrm{IoU}_c = \frac{|\hat{Y}_c \cap Y_c|}{|\hat{Y}_c \cup Y_c|}, \qquad \mathrm{mIoU} = \frac{1}{5}\sum_{c \in \mathcal{C}} \mathrm{IoU}_c.$$
  类计数在场景间池化后再计算 IoU，避免缺失类–场景对引入虚假满分。

## 实验与结果
- **数据集**：CityLayout-100，源自 IRSAMap V2 的 100 张 512×512 近垂直裁剪；按标注土地覆盖实例数分难度：Easy ≤17、Medium 18–23、Hard ≥24。评估类：building、road area、sport、vegetation、water；道路线标注仅作诊断。
- **基线/设定**：完整 Code-as-City 管线；对照变体为**无语义布局先验**的同管线。模型侧：先验由 gpt-image-2 生成，MLLM 解析由 gpt-5.5 完成。
- **主要结果**（Table I，$N=100$）：
  - 完整系统：**mIoU 41.1%**，**GIoU 48.3%**，Precision 65.8%，Recall 64.6%，F1 65.2%。
  - 类-wise（Table II）：Water 59.5%、Vegetation 53.1%、Building 44.8%、Sport 34.2%、Road 14.0%。
  - 按难度（Table III）：Easy mIoU 42.3 / GIoU 48.5；Medium mIoU 36.3 / GIoU 50.9；Hard mIoU 42.7 / GIoU 45.6。
- **先验消融**（Table IV）：移除语义布局先验后 mIoU 降至 36.3%（−4.8）、GIoU 降至 42.5%（−5.8）、F1 降至 59.7%（−5.5）。分项变化：Building +17.6、Road +4.0、Sport −8.3、Vegetation +2.7、Water +8.4。
- **结论**：可执行表示在图像平面仍保持可测一致性；道路面积 IoU 对缓冲宽度/边界误差敏感，但道路仍保持命名与连通；难度并非单调相关，边界模糊与稀有类几何独立影响结果。

## 相关工作脉络
1. **遥感定位/分割**（DOTA、Mask R-CNN、iSAID、DeepLab）：仅输出像素/实例级定位，不要求可再生结构与持久身份；本文在其之后引入**可执行城市代码**并保留投影度量。
2. **向量化土地覆盖与拓扑制图**（IRSAMap）：推进至向量对象与拓扑感知映射，但仍不要求从单图恢复可再生构建；本文更早起点，直接从图像恢复对象与关系。
3. **程序化/结构化城市表示**（Context-sensitive shape grammars、CityJSON）：在规则/几何已知时有效；本文解决其**前置问题**——从单俯视图恢复所需对象与关系。
4. **可执行视觉推理**（VISPROG、ViperGPT、LayoutGPT、3D-GPT、Holodeck）：面向通用视觉、语言条件生成或室内布局；本文面向**户外道路网络与异质土地覆盖**，并用单一程序同时支撑 2D 分割兼容投影与 3D 场景。
5. **室内顶视代码生成**（Code-as-Room）：方法与精神相近，但场景域不同；本文验证该方法可扩展至更复杂的室外城市结构与多类土地覆盖。

## 局限性与未来方向
- 单视角近似恢复高度与外观，**平面组织为主**，难以获得精确 3D 度量。
- 当前pipeline**未使用视觉自迭代**，依赖预设修复路径，面对复杂/歧义场景可能不稳定。
- 先验若不准确会传播至可执行几何（如 sport 类下降 8.3%），先验质量对总体性能影响显著。
- 难度与性能非单调，**边界模糊与稀有类几何**对结果影响未被充分建模。
- 评估仅 100 景，规模有限；跨城区、跨传感器、跨尺度的泛化能力待验证。
- 未来可将结构化对象与几何经人工审核转化为 CityJSON/OSM2World 等工作流，支持 map-to-3D 资产维护。

## 研究启发与可借鉴点
1. **先验引导的分解解析策略**：用轻量图像模型生成对齐的类别/足迹先验，再按依赖顺序调用 MLLM，可显著降低多步生成的累积错误；适用于多阶段结构化生成任务。
2. **共享几何 + 多视图同步再生**：同一程序产物同时生成 2D 投影与 3D 视图，使编辑行为在两视图一致；可迁移至任意需要多视图一致性的程序化生成任务。
3. **受限 API + 执行校验 + 预设修复**：将大模型输出约束为可执行代码并引入确定性校验/修复回路，提升稳定性；可泛化到其他代码生成型视觉任务。
4. **类池化 IoU 评估协议**：跨场景池化类计数以避免缺失类–场景对引入虚假满分，评估更稳健；可作为多类不均衡场景的推荐评估方式。
5. **从检测/分割到可执行资产的工作流升级**：把传统遥感产物升级为可检查、可编辑、可再生的结构化程序，为后续 GIS/数字孪生接入提供更友好接口。

## 关键术语表
- **MLLM（Multimodal Large Language Model）**：融合图像与语言的多模态大语言模型，本文用于多阶段城市元素解析。
- **Code-as-City**：本文提出的“图像→城市代码”范式，以可执行布局程序为核心预测。
- **Semantic layout prior（语义布局先验）**：由图像模型生成的五类对齐色彩/足迹先验，用作 MLLM 解析的平面约束。
- **Typed graph / constrained layout API**：带稳定 ID、规范坐标与类型化关系的城市图，以及 `add_road/add_building/add_open_space/relate` 等受限操作接口。
- **Orthographic semantic projection（正交语义投影）**：将同一布局按固定调色板栅格化得到的 2D 语义图，用于像素级 IoU 评估。
- **mIoU / GIoU**：分别对五个池化类的 IoU 取平均与在全局池化计数上计算的 IoU。
- **CityLayout-100**：基于 IRSAMap V2 的 100 景 512×512 评估集，按实例数分 Easy/Medium/Hard。
- **IRSAMap V2**：大规模高分辨率土地覆盖矢量图数据集，本文的源数据。
