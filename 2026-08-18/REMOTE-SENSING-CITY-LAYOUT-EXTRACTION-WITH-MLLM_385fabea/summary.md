# 论文速读：REMOTE-SENSING-CITY-LAYOUT-EXTRACTION-WITH-MLLM

## 一句话总结
本文提出 **Code-as-City** 框架，将单张俯视遥感 RGB 图像转化为可执行的城市布局程序代码；该代码执行后可同时生成可与遥感掩码进行像素级比较的正交语义投影与可渲染 3D 城市场景，实现"检测/分割 → 可编辑、可再生成的城市资产代码"的跨越。

## 研究问题与动机
- 现有遥感输出（检测框、实例掩码、矢量边界）仅定位类别与支撑图像平面评分，**不保留对象持久身份、类型化关系、拓扑结构与再生成规则**，难以直接作为可维护的城市资产。
- 结构化/程序化城市表示（如 CityJSON、形状文法）需要明确的对象与构建逻辑，但单俯视图无法直接提供这些内容，**从视觉观测到可执行程序之间的缺口未被填补**。
- 既有 Code-as-Room 等工作聚焦室内场景，**缺少针对户外道路网络与异质地物（道路、建筑、运动场、植被、水体）的单一程序表示**。
- 需要一个同时支持"图像平面分割风格评估"与"可检查/可编辑的可执行程序"的新型任务定义与评测协议。

## 核心贡献（创新点）
1. **提出 image-to-city-code 任务定义**：以可执行布局程序为预测目标而非终端栅格/矢量，使命名对象与类型化关系在渲染前后保持一致。
2. **引入语义先验引导的分步 MLLM 解析**：由图像模型生成对齐的五类语义布局先验 $M$，指导三条有序 MLLM pass（道路 → 土地覆盖与关系 → 建筑）逐步累积记录，区别于纯端到端分割或仅靠 RGB 驱动的大模型推理。
3. **设计确定性归一化 + 受限布局 API + 可恢复执行管线**：将 MLLM 产出转为稳定 ID、规范坐标与类型化关系（连通/包含/邻接/服务/对齐），并用固定 Three.js 渲染器生成 2D 正交投影与斜视 3D 视图，共用同一组命名对象与几何。
4. **发布 CityLayout-100 评测集并给出耦合 2D/3D 指标**：基于 IRSAMap V2 的 100 个场景，按难度假标签划分 Easy/Medium/Hard，同时报告 mIoU、GIoU、Prec./Rec./F1。

## 方法详解
- **任务契约**：输入近垂直 RGB 图像 $I$，输出受约束的 Python 布局程序；同一段程序经执行产生**正交语义投影**（用于像素级对比）与**斜视 3D 布局**，使用规范化几何与类型化关系（道路连通、空间邻接等）。开放空间用 `open_space` 泛型可渲染地面对象表示，由语义类型区分植被/水体/运动场；建筑与道路有专属构造函数。
- **五类语义布局先验 $M$**：由图像模型（实验中为 gpt-image-2）从 $I$ 生成，提供对齐的类别与足迹证据，作为每条 MLLM 调用的主 planimetric 约束；RGB 图像 $I$ 同时提供身份、功能、关系、屋顶外观与近似高度线索。
- **三段有序 MLLM 解析**：
  1. **道路 pass**：恢复中心线、宽度、交叉口与连通性。
  2. **拓扑 pass**（依赖道路记录）：提取开放空间区域与类型化关系。
  3. **建筑 pass**（依赖前两步累积记录）：识别个体足迹与重复建筑群。
  各 pass 的坐标均归一化至原图像帧，后续 pass **扩展共享对象库存而非覆盖**。
- **确定性归一化与受限 API**：将三段记录转化为稳定标识符、规范坐标与类型化关系；通过序列化器输出为基于闭合 layout API 的 Python 代码，主要操作为 `add_road`、`add_building`、`add_open_space`、`relate`，schema 专用构造函数覆盖交叉口与重复建筑群。
- **执行与恢复**：在子进程中限时执行生成的程序并返回 JSON；进行畸形几何、重复 ID、无效关系端点等检查；失败时走预定义恢复路径（修复畸形 JSON、拓扑重试、确定性拓扑修复），**不使用视觉自迭代**。
- **共享渲染与评估**：道路中心线按估计宽度缓冲，建筑多边形按近似高度拉伸，语义开放空间生成低表面；Three.js 生成斜视 3D 视图，正交投影器以固定调色板光栅化**同一套对象几何**。对类别 $c$：
  $$
  \mathrm{IoU}_c = \frac{|\hat{Y}_c \cap Y_c|}{|\hat{Y}_c \cup Y_c|}, \qquad \mathrm{mIoU} = \frac{1}{5}\sum_{c \in \mathcal{C}} \mathrm{IoU}_c
  $$
  类别计数在各场景间先聚合再计算 IoU，避免缺失类别-场景对引入人为完美分。

## 实验与结果
- **数据集**：CityLayout-100，取自 IRSAMap V2 的 100 个近垂直 512×512 裁片；按标注实例数划分为 Easy（≤17）、Medium（18–23）、Hard（≥24）。评分类别：building、road area、sport、vegetation、water。
- **基线定位**：本文定位为**全新任务**（image-to-city-code），不与常规分割/检测模型直接对比；完整系统自身即 baseline（Table I/II）。
- **主要数字**：
  - 完整系统：**mIoU = 41.1%**，**GIoU = 48.3%**，Prec. = 65.8%，Rec. = 64.6%，F1 = 65.2%（Table I）。
  - 分项 IoU：Water 59.5%、Vegetation 53.1%、Building 44.8%、Sport 34.2%、Road 14.0%（Table II）。
  - 难度分层：Easy mIoU=42.3 / GIoU=48.5；Medium mIoU=36.3 / GIoU=50.9；Hard mIoU=42.7 / GIoU=45.6（Table III）。
  - 语义先验消融：去掉先验后 mIoU 下降 4.8 pts（36.3→41.1），GIoU 下降 5.8 pts（42.5→48.3），F1 下降 5.5 pts（Table IV）。
- **关键结论**：道路面积 IoU 偏低主要源于缓冲宽度与边界误差，但底层道路仍保持命名连通性；建筑/植被/水体重叠较好；语义先验对分解式 MLLM 空间推理提供显著 grounding 收益，但也存在错误先验向可执行几何传播的风险（如 sport 类别出现 -8.3 pts 下降）。

## 相关工作脉络
1. **遥感检测/分割**（DOTA、Mask R-CNN、iSAID、DeepLab 等）：聚焦图像平面定位与像素分类，**不要求可再生成的构建逻辑与持久身份**。
2. **IRSAMap（V2）**：面向大规模高分辨率土地利用图矢量化的基础数据集，本文借此派生 CityLayout-100，但任务从"矢量地图"推进到"可执行城市代码"。
3. **程序化/结构化城市表示（Shape Grammars、CityJSON）**：关注一旦规则或几何就绪后的资产管理；本文**提前介入**——从单俯视图恢复实例化所需对象与关系。
4. **VISPROG / ViperGPT**：以 Python 执行为中介的视觉推理，适用于通用场景；本文将其范式移植到**户外道路-地物 heterogenous 网络**。
5. **LayoutGPT / 3D-GPT / Holodeck**：语言引导的布局与 3D 生成；主要面向一般视觉推理或室内空间，**不耦合遥感分割指标与 2D/3D 双视图联动**。
6. **Code-as-Room**：从俯视图生成可执行室内场景；本文扩展至室外复杂路网与五类地物，并设计正交投影度量。

## 局限性与未来方向
- 单视图高度估算近似、外观属性不精确，导致建筑高度与道路缓冲区误差较大（Road IoU 仅 14.0%）。
- 依赖商业闭源模型（gpt-image-2、gpt-5.5），可复现性与成本受限。
- 不使用视觉自迭代；错误先验会向下游几何传播（sport 类别 IoU 在消融中出现负向变化）。
- 场景规模受限（N=100），Hard 场景中边界歧义与稀有类几何仍带来挑战。
- 未来方向包括：引入多视角/深度线索改善高度估计；探索开源 MLLM 替代；加入视觉自我修正循环；对接 OSM2World 等 Map-to-3D 资产维护流程。

## 研究启发与可借鉴点
1. **语义先验引导的分步解析**：用轻量图像模型预先生成对齐的先验地图 $M$ 作为 MLLM 的 planimetric 约束，显著降低分解式推理的不确定性，可在其他"视觉 → 程序"任务中复用。
2. **两段式归一化 + 受限 API + 执行恢复**：将 MLLM 的开放式输出收敛到闭合 schema，配合超时子进程与预定义修复路径，保证程序可执行性；这一"生成-校验-恢复"范式可迁移至其他 code-as-X 任务。
3. **2D 正交投影与 3D 视图共享几何**：单一执行产物同时支持分割风格 IoU 评测与三维可视化，使"可检查/可编辑的代码"与"可量化的像素指标"并存，为后续人机协同修正提供统一入口。
4. **难度分层评测（Easy/Medium/Hard）**：以实例数划分难度并揭示非线性趋势，提醒读者避免简单线性外推；可作为后续遥感受控生成任务的设计参考。
5. **消融语义先验揭示传播风险**：证明 grounding 收益并非均质，个别类别可能因先验误差受损；启示未来工作需设计"选择性信任先验"机制。

## 关键术语表
- **Code-as-City**：将单张遥感俯视图像映射为可执行城市布局程序的新任务与框架，执行后同时产出 2D 正交语义投影与 3D 可渲染场景。
- **Semantic Layout Prior（语义布局先验）**：由图像模型从 RGB 生成的五类对齐先验掩码，作为 MLLM 解析的 planimetric 约束。
- **Typed Graph（类型化图）**：经确定性归一化后的城市对象图，包含稳定 ID、规范坐标与连通/包含/邻接/服务/对齐等类型化关系。
- **Restricted Layout API**：闭合的程序接口，仅提供 `add_road`、`add_building`、`add_open_space`、`relate` 等受限操作以保证生成代码的可执行性。
- **Orthographic Semantic Projection（正交语义投影）**：用固定调色板对共享对象几何做正交投影视图的光栅化，用于与遥感掩码进行像素级 IoU 对比。
- **mIoU / GIoU**：mIoU 为五类聚合 IoU 均值；GIoU 为跨类别聚合后的全局 IoU，避免缺失类别-场景对引入人为满分。
- **CityLayout-100**：基于 IRSAMap V2 的 100 个 512×512 近垂直遥感裁片组成的新评测数据集，按实例数划分 Easy/Medium/Hard。
- **IRSAMap V2**：大规模高分辨率土地利用图矢量化的基础数据集，本文以其裁片构造 CityLayout-100。
