# 论文速读：StreamSoccer: Event-Driven Memory for Streaming Soccer Commentary

## 一句话总结
本文提出了 StreamSoccer，一个以**事件记忆（Event Memory）**为中间表示的流式足球解说系统；它将持续到来的视频流组织为固定预算的事件状态单元，在支持当前事件、近期窗口、历史记忆三个互补时间尺度解说的同时，保持计算与内存的有界增长，在共同因果锚点上分别取得当前事件与历史记忆 CIDEr 第一、近期窗口 CIDEr 第二的成绩，且全场比赛 90 分钟内 p95 实时因子维持在 0.10–0.22，无随历史累积的持续退化。

## 研究问题与动机
- **流式视频理解的状态组织单元缺失**：现有通用流式视频语言模型以帧/视觉 token 或 KV cache 为单位组织历史，缺乏把语义过程当作可激活–更新–关闭–检索的状态单元并持续维护的机制。
- **足球解说对多时间尺度上下文的要求**：一场完整比赛需要覆盖"刚结束事件的描述""近期多事件聚合""较早事件的回溯关联"三种尺度，单一时序窗口或离线全片输入均无法满足。
- **长历史计算与内存的有界性约束**：现有方法常采用逐帧压缩或 KV 缓存，随比赛进行计算与上下文持续膨胀；例如 VideoLLM-online 在长赛后接近或突破实时阈值，TimeChat-Online 在约 55 分钟触及上下文上限。
- **数据与评测口径的不足**：既有足球解说数据集（SoccerNet-Caption、MatchTime、GOAL 等）多为离线剪辑或给定时间戳的场景，缺少"仅在输出时刻之前可见信息"这一因果观测截止约束的系统化三轨数据集与分层评测协议。

## 核心贡献（创新点）
1. **将足球解说形式化为带因果观测截止的流式生成任务，并构建三轨数据集**：定义当前事件、近期窗口、历史记忆三个互补轨道，每条样本携带明确的观测截止时间与源事件溯源，使用 match-disjoint 划分，并内置未来信息检查。区别于 SoccerNet-Caption/MatchTime 等离线/给定时间戳设定。
2. **提出以事件记忆为核心的中间表示与全生命周期管理**：通过 Streaming Event Memory Encoder 维持固定预算的活跃事件状态，在操作转换与最大时长双重信号下关闭并固化完成事件记忆，随后异步重组为可检索的历史记录；区别于 StreamingVLM、TimeChat-Online 等以帧/token/cache 为单位、不以事件语义生命周期为组织的方案。
3. **构建统一的多上下文解说生成器与规则辅助调度器**：单一生成接口共享记忆到语言的投影 $P_\theta$ 与语言模型，三种轨道仅在不同上下文配置（当前完成记忆、活跃+本地缓冲拼接、检索文本）下运行；调度器基于固定阈值与优先级规则在四种模式（当前事件/近期窗口/历史记忆/静默）中选择。区别于 SoccerComment、GameSight 等依赖预定义片段或离线输出的管线。
4. **设计分层评测协议与原始视频效率基线**：引入共同锚点质量控制、事件记忆表征对比、内存范围消融、原始视频跨 58 场比赛的 RTF p95 增长曲线与 LLM 盲审语义偏好，形成可与声明严格对齐的证据矩阵。区别以往仅报告单一指标或兼容比较。
5. **公开三轨流式足球解说数据与冻结结果溯源**：基于 SoccerNet 动作标注与 MatchTime 解说对齐，产出 27,639 样本的三轨数据集，并为每项实验提供 artifact ID、协议哈希与重放记录。

## 方法详解
- **整体流程**：每次流入视频片段经冻结的 Qwen3-VL 视觉编码器输出视觉 token，由 Clip Event Adapter 压缩为固定数量的 clip 级事件 token $E_t \in \mathbb{R}^{K_m \times d_m}$（$K_m=9, d_m=1024$），其中 $E_t[0]$ 摘要当前片段，其余保留分布事件信息。随后在线事件更新将 $E_t$ 并入活跃事件状态；若事件关闭，已完成的记忆 $M_j^c$ 进入近期本地缓冲区并异步重组为文本历史事件记录。规则辅助调度器选择解说轨道后，多上下文生成器投影所需状态并通过共享语言模型产出解说。
- **在线事件记忆编码**：先由 Operational Transition Head 比较 $E_t[0]$ 与上一活跃状态 $M_{t-1}$，预测操作转换指示 $b_t$。若继续，则通过槽门控融合：$\widetilde{M}_t = (1-G_t) \odot M_{t-1} + G_t \odot \mathcal{U}(M_{t-1}, E_t)$，始终维持 $K_m$ 个 token 的固定预算。同时设置最大事件时长 $D_{\max}=24\text{s}$ 作为确定性兜底：$\rho_t = [\text{dur}(M_{t-1}) \ge D_{\max}]$，$r_t = b_t \vee \rho_t$，$M_t = (1-r_t)\widetilde{M}_t + r_t \mathcal{T}(E_t)$，当 $r_t=1$ 时将 $M_{t-1}$ 关闭为不可变完成事件记忆 $M_j^c$。训练使用 teacher-forced reset，并对时长兜底位置屏蔽操作转换监督；推理时 $b_t$ 与 $\rho_t$ 共同控制关闭。
- **记忆到记录重组**：完成事件记忆经记忆到语言投影 $P_\theta(\cdot)$ 映射为固定长度的软前缀，并在最小因果可用比赛上下文 $x_j^{\text{ctx}}$ 条件下由语言模型生成事件记录字幕 $c_j$，再由确定性程序附加时间、动作、事件类型、比赛状态等结构化元数据形成可检索记录 $R_j$，随后进入长期记忆库 $\mathcal{L}_t$。
- **多上下文解说生成器**：共享 $P_\theta$ 与语言模型，三种轨道的软前缀配置不同：当前事件直接投影刚关闭的 $M_j^c$；近期窗口与历史记忆将当前活跃记忆与所选本地完成记忆拼接后投影，得到 $Z_t$；历史记忆轨道额外将检索到的记录 $\mathcal{R}_t$ 序列化为文本加入提示。由此实现"紧凑隐式上下文+文本历史上下文"的统一生成接口。
- **规则辅助调度**：当前事件模式要求显著刚完成事件并满足冷却；近期窗口模式要求足够数量的完成事件并过周期与事件邻近门；历史记忆模式要求检索记录满足时间、相关性与冷却条件；否则静默。多模式并行满足时按历史>事件>近期窗口优先级选择。调度策略为确定性规则，非学习型策略。
- **训练目标**：共三阶段。Stage 1 训练事件记忆编码器，损失包含片段级非对称稀疏多标签动作识别、有效位置 focal BCE 操作转换预测、完成事件的多标签动作集 focal BCE、以及粗粒度事件类型交叉熵；时长兜底位置不参与操作转换正监督。Stage 2 训练投影与 LoRA 从 $M_j^c$ 生成字幕，仅对 assistant 字幕 token 上自回归损失。Stage 3 在三轨道任务平衡生成损失基础上，叠加保留阶段 1 语义的 $\mathcal{L}_{\text{retain}}$、上下文路由的 $\mathcal{L}_{\text{route}}$、本地候选排序的 $\mathcal{L}_{\text{local}}$ 与历史候选检索的 $\mathcal{L}_{\text{retr}}$；排名损失仅在存在合法正负样本时计算。 backbone（Qwen3-VL-8B-Instruct）冻结，语言侧采用 LoRA（$r=8, \alpha=16$）。
- **在线运行时**：Clip 时长 4s、采样 2 FPS；本地事件记忆缓冲 horizon 180s、最多选 4 个完成事件；历史检索为 embedding top-3、同半场且间隔≥90s；当前事件冷却 12s，近期窗口间隔 120s 且最少 3 个事件，完成后冷却 20s，历史冷却 180s 且最少 8 条记录，历史分数阈值 0.12；解码确定性、评论最多 96 token、记录字幕最多 64 token。

## 实验与结果
- **数据集与划分**：基于 SoccerNet 动作标注与 MatchTime 解说对齐，构建三轨流式解说数据共 27,639 样本（当前事件 15,189、近期窗口 7,127、历史记忆 5,323）；按场次 disjoint 划分为训练 19,641、验证 4,209、测试 3,789。自动因果校验拒绝在观测截止后形成的任何输入/监督。
- **评测基线与指标**：严格对比共享测试集、因果截止、输出锚点与解码预算；兼容对比披露差异。指标含 CIDEr（100×）、BLEU-4、BERTScore-F1（RoBERTa-large layer 17）。原始视频效率以 p95 每分 RTF 衡量。
- **主要结果**：在共同因果锚点上，StreamSoccer 取得当前事件 CIDEr 38.62、近期窗口 CIDEr 23.96、历史记忆 CIDEr 17.39；当前事件与历史记忆 CIDEr 排名第一，近期窗口排名第二（落后于 UniSoccer 的 27.85）。BERTScore-F1 三项分别为 0.9734、0.9612、0.9636。
- **效率结果**：在 58 场源清晰比赛的 174 条原始视频运行中，StreamSoccer 的 p95 每分 RTF 全程维持在约 0.10–0.22，无随比赛历史累积的持续增长；峰值 VRAM p95 约 17,996 MiB。对比中 StreamingVLM 约 0.31–0.47，VideoLLM-online 后期逼近/超过实时阈值，TimeChat-Online 在约 55 分钟达到上下文上限。
- **表征与范围消融**：递归事件记忆在记忆到记录字幕任务上对固定时间池化提升 Tok-F1 +0.0533、CIDEr +21.68；对操作事件池化提升 Tok-F1 +0.0351、CIDEr +15.21。内存范围方面，仅当前记忆 → 加本地缓冲 → 全量三范围，三轨 CIDEr 单调提升，近期窗口增量最大（+6.01）。
- **语义盲审**：单judge（temperature 0 GPT-5.6-terra）四向盲审下，StreamSoccer 在全部 3,789 个锚点上的严格胜率 93.16%（95% CI [92.32%, 94.01%]），各轨道均优；可用性加权，其他方法在多数锚点返回 NO_RESPONSE。
- **最强结果与提升**：当前事件 CIDEr 38.62，较 SoccerMaster（33.35）提升 +5.27；历史记忆 CIDEr 17.39，较 SoccerMaster（7.37）提升 +10.02；近期窗口 CIDEr 23.96，较 SoccerMaster（23.46）微幅领先 +0.50。整体全系统相较仅当前记忆，近期窗口获得最大增益。

## 相关工作脉络
- **SoccerNet 系列与 MatchTime/GOAL**：提供足球视频理解的领域数据与任务设定，但以离线剪辑或给定时间戳为主；本文将其转化为因果流式任务并定义三轨语义覆盖。
- **通用流式 VLM（StreamingVLM、TimeChat-Online、VideoLLM-online、StreamBridge 等）**：采用分层压缩、固定视觉 token 预算或 KV 缓存组织连续处理，但历史单元围绕帧/token 而非事件生命周期；本文证明事件记忆在长赛程下保持更稳定效率。
- **长视频记忆与检索（MART、MovieChat、MA-LMM、VideoRAG、SoccerComment）**：历史上下文多为通用内部状态或预建语料；本文从流式完成事件记忆中在线推导可检索记录，强调"流内产生-流内复用"的一致性。
- **领域专用模型（UniSoccer、SoccerMaster、MatchAware、GameSight）**：在离线/片段场景下具备强表达能力；本文定位差异在于维持状态持续演进并支持三种时间尺度解说，而不仅提升单轨离线指标。
- **流式视频理解的基础效率工作（Flash-VStream、StreamFormer）**：面向通用长视频，未建模足球领域的事件语义边界与操作转移；本文用规则派生的操作事件作为内存生命周期控制单元，兼顾效率与语义。
- **数据构建与因果标注**：SoccerNet-Caption 等提供字幕但缺乏因果截止与源事件溯源；本文引入确定性 football 规则完成操作事件化，并做 match-disjoint 与未来信息自动拒绝，提升评测严格性。

## 局限性与未来方向
- 操作事件为基于规则确定性派生的状态控制单元，并非无约束的自然语义事件发现；40.2% 的事件由 24s 时长兜底关闭，边界可能与真实语义边界存在偏差。
- MatchTime 对齐仅覆盖全部操作事件的 9.13%，评测集中在有解说监督的显著时刻，非均匀覆盖所有比赛状态。
- 主表格结果来自参考锚点重放，使用 oracle 操作关闭、当前事件对齐、标签辅助动作/类型元数据与记录就绪干预；自由调度器的真实异步表现并未作为排名证据。
- 部署的调度器为确定性规则辅助策略，未引入学习型 speaking-policy；实际比赛中的解说时机选择并非本文核心贡献。
- 实验单一联赛/语料生态，跨联赛、跨语言及不同转播风格的泛化尚未验证。
- 已生成的事件记录字幕为模型输出而非人工核实事实；论文未对记录级事实正确性作声称。
- 当前原始视频 artifact 未仪器化 retained context-token 计数，零值字段不能直接作为未保留上下文的证据。
- 单 judge 盲审（GPT-5.6-terra temperature 0）用于语义偏好排序，不等同于人类偏好或断言级事实正确性。

## 研究启发与可借鉴点
- **事件生命周期作为流式多模态的中间表示范式**：将"激活-更新-关闭-重组-检索"作为固定预算状态单元的全生命周期，可迁移至篮球、网球等其他具有明确事件边界的体育流式理解，乃至新闻直播、会议录制等场景。
- **操作转移预测与确定性时长兜底的组合设计**：学习型 $b_t$ 捕捉语义边界，$\rho_t$ 保证最坏情况有界，这种"学习+规则"双保险可用于其它需要稳定状态切分的流式任务，避免无限累积。
- **三层内存范围的分层利用策略**：当前完成记忆、本地短期缓冲、异步构造的可检索历史记录构成从即时到长期的连续谱；不同轨道共用同一投影与生成接口，可推广到多尺度问答/摘要联合系统。
- **共同锚点的因果严格评测与协议矩阵**：通过区分样本级条件评测、参考锚点重放、自由调度重放与原始视频效率四条轨道，并为每项声明配套证据-解释边界，值得在多模态流式评测中复用。
- **配对匹配的代表性消融**：在相同视觉支持与语言读出下比较递归事件记忆、操作事件池化与固定时间池化，分离了"事件对齐"和"递归状态形成"两处贡献，实验设计干净，可借鉴于表示学习的归因分析。

## 关键术语表
- **Event Memory（事件记忆）**：以固定预算 token 集合编码一个正在进行的比赛事件的紧凑潜表示，持续吸收新片段并在事件关闭后冻结为可复用状态。
- **Operational Transition（操作转换）**：由规则与学习头共同决定的事件边界切换信号，触发当前活跃状态关闭并导出为完成事件记忆。
- **Memory-to-Record Consolidation（记忆到记录重组）**：将完成事件记忆经投影与语言模型生成字幕，再确定性附加元数据形成可检索文本记录的过程。
- **Rule-Assisted Scheduler（规则辅助调度）**：基于固定阈值、冷却期与优先级的确定性策略，在四种解说模式（当前事件/近期窗口/历史记忆/静默）间做出选择。
- **Common-Anchor Evaluation（共同锚点评测）**：固定任务类型、观测截止与参考输出时刻后进行因果重放的评测方式，保证所有方法在同一合法历史下比较。
- **Observation Cutoff（观测截止）**：每条样本允许使用的最晚可见时间点，任何在此之后形成的视频、事件或信息均被排除，避免未来泄露。
- **Multi-Context Generator（多上下文生成器）**：共享投影 $P_\theta$ 与语言模型的统一生成接口，按轨道差异仅改变输入上下文配置（当前/近期/历史+检索文本）。
- **RTF p95（第 95 百分位实时因子）**：每分工作量的端到端处理墙钟时间与视频时长之比的上尾度量，<1 表示快于实时；用于衡量长历史下的资源缩放。

- **数据集**：基于 SoccerNet 与 MatchTime 构建的三轨流式解说数据（27,639 样本），划分见论文 Table B.2；动作→操作事件的确定性规则在 Appendix B 给出，数据构造流水线与因果校验细节充分披露。公开性：论文提供 artifact ID 与协议哈希等可溯源记录，但未提供独立的代码仓库链接。
- **代码/权重**：骨干为 Qwen3-VL-8B-Instruct（冻结），模型参数与训练 recipe 见 Appendix C；冻结 checkpoint step 1,000/42 用于主表结果，step 7,000/42 用于自由调度审计。论文未提供独立开源代码仓链接，仅通过 artifact 溯源表提供结果对应关系。
- **关键超参**：$K_m=9$、$d_m=1024$、$D_{\max}=24\text{s}$、2 FPS/4s clip、LoRA $r=8,\alpha=16$、本地缓冲 180s 最多 4 个事件、历史 top-3 同半场间隔≥90s、当前冷却 12s、近期间隔 120s 最少 3 个、历史冷却 180s 最少 8 条、历史分数阈值 0.12、解码上限 96/64 token。Stage 1 学习率 $10^{-4}$、Stage 2 投影 $10^{-4}$ / LoRA $10^{-5}$、Stage 3 LoRA $2\times10^{-5}$ / 投影 $3\times10^{-5}$，warmup 500 step；Stage 3 共 10k 步，前 5k 教师强制上下文、后 5k 暴露运行时上下文并将预测上下文比例从 0.10 逐步升至 0.50（每 250 步）。
